# OBDLink MX+ — a real session

Captured 2026-09-03 over Bluetooth Classic (RFCOMM/SPP), Windows COM5, 38400
baud. Kept because it is the only recording of a real adapter on a real car in
this repository, and four decoder faults were found against it that no unit
test had caught. Read-only throughout: mode 04 was never sent.

## What the adapter is

```
BTHENUM\{00001101-0000-1000-8000-00805F9B34FB}_LOCALMFG&0002\...
```

Windows maps it to a COM port under the **standard** Serial Port Profile
(`0x1101`). Worth recording, because the natural theory for "the chooser is
empty on my phone" is a vendor-specific service class ID — and for this
adapter that theory is wrong. It reports itself as an ELM327 v1.4b.

## Ignition off — the trap

```
ATZ   → ELM327 v1.4b
ATRV  → 12.3V
0100  → SEARCHING...  UNABLE TO CONNECT
03    → SEARCHING...  UNABLE TO CONNECT
```

**12.3 V and no ECU.** The socket is powered from the battery, so the adapter
pairs, answers, and reports a healthy bus voltage whether or not the car is
awake. `UNABLE TO CONNECT` decodes to zero codes, and zero codes used to be
reported as "no codes found" — a clean bill of health for a car nobody had
actually asked.

## Engine running

```
ATS1  → OK
ATSP0 → OK
ATRV  → 12.2V
0100  → 41 00 B6 3F A8 13
        41 00 88 18 00 03
ATDP  → AUTO, ISO 15765-4 (CAN 11/500)
03    → 43 00
        43 00
07    → 47 00
        47 00
0A    → 4A 00
        4A 00
```

Two ECUs answer, so every mode returns two lines — which is why each line is
decoded independently rather than the reply being flattened first.

`43 00` is the shape that matters: on CAN the byte after the mode reply is a
**DTC count**, here zero. Pairing bytes from the count rather than after it
shifts every code by one byte, so a car with P0133 and P0420 reads as P0201.
Payload parity is what distinguishes the two framings — CAN sends `1 + 2n`
bytes, the older protocols `2n` — including when a short CAN frame is padded,
since padding is in whole pairs.

## Reproducing it

```powershell
$port = New-Object System.IO.Ports.SerialPort 'COM5',38400,'None',8,'One'
$port.Open(); $port.Write("ATZ`r"); Start-Sleep -Milliseconds 1800
$port.ReadExisting()
```

Substitute the COM port Windows assigned; `Get-PnpDevice -Class Ports` lists
them, and the adapter's Bluetooth address appears in the instance ID.
