# Translations

Four languages are offered: English (United States), English (Canada),
français (Canada) and español (México).

**en-US is the source language and has no catalogue.** Every `msgid` in the
code is already US English, so gettext falling through to it is correct.
Adding an empty `locale/en_US/` would be 1,777 blank entries that churn on
every extraction and change nothing.

## These are machine-drafted

The fr-CA and es-MX catalogues were drafted by machine and have **not been
reviewed by a native speaker**. They are complete — every string is
translated, nothing falls back to English — and they are a first draft.

Each string was translated in isolation, which is where that approach is
weakest: an English label that reads as a noun on one screen and a verb on
another gets one guess, and shop vocabulary is full of both. Corrections are
welcome and are the point. Shop terms in particular are worth a second look:
*balata*, *refacción*, *canje*, *rangée*, *consigne*, *chiffrier*.

en-CA is different: it is generated by spelling rule from the source, and
covers exactly ten strings — `licence plate`, `labour`, `catalogue`,
`Cancelled`, `Totalled`, `grey-market`. Everything else falls through, because
the source is already correct Canadian English. Deliberately left alone:
`meter` (Canadian keeps it for a gauge and spells the *unit* `metre`, and
every use here is an odometer), `check` (inspection, never payment), and
`tire` (the Canadian spelling is the American one).

## Changing a translation

Edit the `msgstr`. Leave the `msgid` alone — it is the key. Keep every
placeholder (`%(name)s`, `%(counter)s`, `{plate}`) exactly as it appears in
the source; a dropped one is a `KeyError` on a live page.

Then recompile and commit both files:

```bash
docker compose exec app python manage.py compilemessages --ignore venv
```

`.mo` is what ships — `.dockerignore` keeps `.po` out of the image — so an
edited `.po` that nobody recompiled means the running instance disagrees with
this directory. `homeautoshop/core/tests_locales.py` fails when they drift.

## Adding or changing a source string

```bash
docker compose exec app python manage.py makemessages \
    --locale en_CA --locale fr_CA --locale es_MX \
    --ignore 'venv/*' --ignore 'staticfiles/*' --ignore 'data/*' \
    --ignore 'Artifacts/*' --ignore 'docs/*' --no-obsolete --no-wrap
```

New entries arrive with an empty `msgstr` and fall back to English until
somebody fills them in. Changed entries arrive marked `#, fuzzy`, which means
*a person should re-check this* — msgfmt drops a fuzzy entry, so it reads as
untranslated until the flag is removed. Do not clear those in bulk; that is
how a stale translation ships.

A plural must use the same placeholders in every form. gettext refuses
otherwise, which is how a real bug in `notifications.py` was found: its
singular said `%(n)d` and its plural `%(d)d`, so the string had been
untranslatable since it was written and nobody had noticed.
